# リカ・クエスト 3年から6年の拡張設計と改善提案

この文書は、既存の5・6年版を点検したうえで、3・4年を同じRPGに追加するための設計と今後の増補案です。教材は既存と同じ東京書籍「新編 新しい理科」令和6年度版を前提にしています。

## 今回の実装状況

- 全44単元と8観察章を追加・統合。3・4年は基本20・ボス10・おまけ15、観察章は10・5・0。5・6年は基本23・ボス12・おまけ15へ増補し、計2,205レコードになりました。
- 以下の優先不具合を修正。未遭遇優先の抽選、全5体の探索、通常4種の再取得、即時HUD、学び直し、途中再開、ノート、旧セーブ移行・書き出し・読み込みを実装しました。
- 既存の重点修正問題を更新し、基本・ボスに小単元と範囲参照、全問に到達段階と内容版を追加しました。3・4年の先取りでは上級学年の問題を一部共有し、元IDを追跡できます。音・圧力は専用の15問です。
- 全52経路と報酬・装備効果をNodeで検証し、ChromeでPC・タブレット・スマートフォン幅、SVGピクセル、回答後再開、報酬、file直開きを確認しています。
- **基本40・ボス20、各単元の図解問題を厚くする増補、小単元指定探索、技能別の集計表示は今後の作業です。** 以下の数値・機能案を全て実装済みとするものではありません。教材全問の最終専門査読も未完了です。

以下は実装前の調査記録と、その後の増補方針です。実装済みの範囲は上記とREADMEを参照してください。以降の数値には将来目標も含みます。

### 全問に適用する査読項目

1. 対応する小単元と、その学年で扱う内容を特定する。基本・ボスには `subId` と `curriculumRef` を付ける。
2. 正解が一つに定まる条件を設問へ入れる。「何と比べるか」「同じ水量か」「どの植物か」を省略しない。
3. 誤答は同じ話題のよくある誤解から作る。時計・おやつなど、無関係な選択肢で正解が目立つ問題を減らす。
4. 正解だけ極端に長い、正解だけ専門的な言葉を含むといった手がかりをなくす。
5. 言い換えだけの問題は水増ししない。観察、操作、結果、理由、日常の場面へ出題対象を広げる。
6. 解説は「正解は何か」「なぜか」「次に見るポイント」の短い構成にし、基本・ボスに範囲外用語を持ち込まない。
7. 火・薬品・乾電池・集光・夜間観察・水辺・災害は安全面も査読する。家庭での危険な実験を促さない。
8. ルビ、単位、図のラベル、色以外の正誤表示を検査する。3・4年は漢字を増やすより短い言葉を選ぶ。

## 全学年に共通する体験

### 学習ルート

| 場所 | 学ぶ内容 | 解放と報酬 |
| --- | --- | --- |
| 洞窟 | 当該単元の基本、観察、実験の操作 | 基本達成で次単元・城・おまけを解放。EXPと消費アイテム |
| 城 | 当該単元内のデータ読み取り、結果の理由、比較 | 討伐で仲間。初回回答が全問正解なら未入手の通常装備1点 |
| くらしの広場 | 学年内の内容を使う日常生活の問い | 基本・ボスの `context:everyday` 問題を選んで出す。本筋の学習内容として扱う |
| 上の学年チャレンジ | 小学校の先取り、中学内容、科学トリビア | 基本達成後の任意ルート。15問全問正解で単元専用のレア装備。本筋のクリアには不要 |
| 研究ノート | 間違えた問題、観察記録、季節の比較 | ライフなしで復習。正誤と学習記録を保持 |

5・6年では「中学チャレンジ／科学トリビア」を基本表示とし、内容が小学校既習・高校以降なら正しいラベルへ変えます。3・4年のおまけは「上の学年チャレンジ」として、まず一段上の学年へつなぎ、希望する子が中学の入口へ進めるようにします。中学内容の達成で小学校単元をクリア扱いにはしません。

### 問題数と一回の出題数

- 初期実装は全ての番号付き単元で **基本20・ボス10・おまけ15** をそろえる。既存問題のIDと学習記録は保持する。
- 精査後の増補目標は **基本40・ボス20・おまけ15**。基本40問には日常生活問題を10問含める。言い換えの増産ではなく、図・観察・データ・理由を増やす。
- 番号付き44単元の初期バンクは1,980問。新規3・4年の23単元は1,035問の追加。短い8章は基本10・ボス5を目安とし、全体の初期目標は2,100問。
- 増補後は番号付き44単元で3,300問、短い8章を含め3,420問を目安とする。狭い章に無理に同じ問題数を課さない。
- **バンクの問題数と今回の出題数を両方表示する。** 基本は全問コースを標準とし、5問・10問の短いコースも選べる。利用者の選択なしに20問を5問に減らさない。
- 全問コースは5問ごとに小休止・自動保存。短いコースは未出題優先で、出尽くすまでは同じ問題を再抽選しない。
- ボスは1回10問。バンクが20問へ増えたら、小単元の偏りを防いで10問を抽出。おまけのレア判定は専用セット15問すべてへの初回回答で行う。

### 達成度とバトルの分離

学習記録は `answeredCount`、`firstCorrectCount`、`masteredQuestionIds`、技能別の結果で管理します。攻撃力や会心でこの数値を増やしてはいけません。装備はライフ、演出、EXPなどを助けますが、正解数やノーミス判定を変えません。

基本は「学び直し」と「RPG挑戦」を選べる案にします。学び直しではライフを減らさず、全問題を経験し、間違えた内容を解説と復習で確認したら先へ進めます。RPG挑戦では20問中16問以上の初回正解を達成基準の候補とし、小単元の未経験部分があれば補習を出します。80%という基準は実際の利用で調整する提案値です。

敵HPはバトル専用値とします。学び直しの再回答でも敵は倒せますが、最初のミスは消さず、通常・レア装備の全問正解には数えません。RPG挑戦は正解率目標に合う敵HPを設定し、達成度の不足を会心ダメージだけで突破できないようにします。完走時にHPだけを残して結果と矛盾する表示は出しません。

ヒント・盾・復活を使っても、誤答があればノーミスではありません。ヒント利用は独立して記録します。現行との互換性を優先し、正解前にヒントを使っただけではレア資格を失わせません。追加の「ヒントなし」称号は別評価にします。

## 物のとけ方の出会い設計

現在は3体ではなく、登録済みのザコ5体のうち **ソルティン以外の4体** が選出されません。描画関数は5体とも存在します。

| 敵 | 結び付ける学習 | 造形 |
| --- | --- | --- |
| ソルティン | とける、重さ、とけ残り | 食塩の結晶、白いスライム |
| トケルン | すき通る、全体に広がる | 透明感のある体、光のハイライト |
| ミョウバルー | 温度ととける量、冷やして取り出す | ミョウバンの結晶、子ドラゴン |
| ロカガエル | ろ紙、ろうと、ガラス棒、ろ過 | ろ紙のマント。水だけでなく、とけた物もろ紙を通る説明と両立させる |
| ジョーハツバット | 水の蒸発、蒸発皿、取り出す | 蒸発の風を表す羽 |
| クリスタドラゴン | 単元全体の総合 | 結晶の翼、通常ボス |
| 幻晶クリスタドラゴン | 中学先取り15問 | 金の輪・結晶の冠、別IDのレジェンダリー変種 |

出現する候補を単元データで明示し、5問前後のまとまりごとに敵を切り替えます。20問コースでは通常4回の出会いになるため、未遭遇の敵を最優先し、次の挑戦で5体目に会える構造にします。5体を一度ずつ出し切ってから抽選袋を補充します。途中終了でも、実際に表示された敵は「遭遇」、倒した敵だけは「討伐」と保存します。

学習内容に合う敵を優先しつつ、特定の問題構成のせいで候補が永遠に出ないことを防ぎます。小単元を指定して挑む探索も用意し、図鑑の未遭遇カードから該当コースへ移動できます。

3・4年の例は上記の公式年間指導計画の学習内容に沿う案です。先取りは専門語の暗記だけで終えず、既習の現象に新しい言葉や簡単な資料を一つずつ足します。

## データと保存の設計

### 既存ファイルを拡張する範囲

- `data/curriculum.js`: 3・4年23単元と8章を追加。`kind`、`order`、`unlockAfter` を追加して、番号のない章と本筋を区別する。既存 `g5_uXX`、`g6_uXX` は維持する。
- `data/questions/`: 3・4年は `g3_u01_spring.js` から `g3_u11_magnets.js`、`g4_u01_spring.js` から `g4_u12_year_review.js` のように単元別ファイルにする。全て通常のscriptでグローバル登録する。
- `data/monsters-data.js`: 単元別の敵IDを登録。`encounters` を各単元から参照し、themeだけから先頭の敵を選ばない。
- `data/equipment-data.js`: 新テーマの通常4種と、3・4年各単元のレアを追加。レアはthemeではなくunitIdから一意に決める。
- `js/battle.js`: 出題計画、回答評価、画面更新を分ける。学習・RPGの2モード、途中保存、敵の交代を追加する。
- `js/state.js`: 旧セーブを移行。未遭遇の敵、未出題の問題、解答履歴、途中の出題順を保存する。
- `js/map.js`: 3・4・5・6年のタブと学年別配置を設定から生成。季節ルートと植物ルートは明示的な依存関係で解放する。
- `js/svg.js`、`js/monsters.js`: 新テーマの造形を追加。全キャラクターの関数による差し替え設計を維持する。

### 問題の追加メタデータ

```js
{
  id: "g3u07-b-021",
  tier: "basic",
  type: "mc4",
  skill: "concept",
  subId: "g3_u07_s1",
  curriculumRef: "A(3)ア(ｱ)",
  context: "everyday",             // standard | everyday
  targetStage: "elementary3",      // 対象学年。おまけも実際の到達先を示す
  contentVersion: 1,
  stem: "...",
  choices: ["...", "...", "...", "..."],
  answer: 0,
  explanation: "..."
}
```

おまけには `bonusCategory: next_grade | middle | trivia | beyond_middle` と `prerequisiteIds` を加えます。これはルビ表記を含む既存スキーマへの追加であり、通常の4択・○×を変えません。図は `diagramKey` と構造化データを使って自作SVGを描画し、問題文にHTMLを埋め込みません。

### セーブ互換性

キー `rika_quest_save_v1` は当面維持し、JSON内の `schema` を2へ移行する案です。旧スキーマから明示的に移行し、スキーマが変わっただけで全消去しないようにします。移行前のバックアップを、設定のJSON書き出しから取得できるようにします。公開リポジトリへ個人のセーブを含めません。

追加する主な項目は `questionStats`、`encounterBags`、`activeSession`、`settings.lastGrade` です。セッションには問題ID、シャッフル後の選択肢順、回答済み状態、初回の正誤、残りライフ、報酬確定状態を保存します。問題データが更新されて再開できない場合は説明して新しい挑戦へ戻し、確定済みの報酬を二重に付与しません。

レアの取得と `bonusPerfected` は同じ更新で確定します。装備データが未登録で取得できなかった場合に、達成フラグだけが立って以後の入手を妨げないようにします。保存に失敗した際も、保存済みと誤表示せず、そのセッションで得た進捗を失わない回復方法を示します。

消費済みアイテムは0のまま保持します。仲間の効果は4学年分を無制限に合算せず、連れていく仲間を最大2体とする案を検討します。既存の救出済み仲間は図鑑に残し、総所持数と戦闘中の効果を分けます。

## 実装順序と完了条件

1. **不具合の修正**: 敵の選出、通常装備の再討伐報酬、基本のクリア判定、回答直後のHUD、消費アイテム保存を修正し、回帰テストを追加する。
2. **既存問題の精査**: 上記の具体例から着手し、全問の小単元・指導要領・到達学年を整理する。問題IDを保持し、内容の変更を版で管理する。
3. **4学年の土台**: カリキュラム44単元と8章、学年タブ、解放関係、セーブ移行、探索と学習モードを実装する。
4. **3年の完成**: 11単元と植物3章の問題・敵・装備・図を作成する。図で答えられる問題を厚くする。
5. **4年の完成**: 12単元と季節・星5章を作成する。比較資料と一年の観察ノートを厚くする。
6. **増補**: 基本40・ボス20を目標に、生活問題、実験計画、表や図から判断する問題を追加する。安全と範囲の査読を先に通す。

完了判定には次を含めます。

- 全44単元と8章が表示され、3・4年にも洞窟・城・先取り・装備・図鑑が使えること。
- 物のとけ方の5体すべてに、出会えるコースと描画があること。全出現候補に到達可能性テストがあること。
- 同じボスを4回全問正解すると、未入手の通常4種がそろうこと。すべて所持後は二重追加しないこと。
- おまけ15問の初回回答が0ミスの場合だけ単元専用レアを付与すること。ミスの盾無効化、会心、復活が全問正解を偽装しないこと。
- アイテムを使い切って再読み込みしても0のまま、旧5・6年の進捗と装備もそのまま残ること。
- 選択肢の全ての位置に正解が出せ、並べ替えても正解判定・解説・ヒントが一致すること。
- 20問のバンクが勝手に5問で終わらず、短いコースなら選択した出題数と累計の履修数が分かること。
- 回答直後にHPとライフが変化し、敵が倒れた画面とクリア結果が一致すること。
- 基本・ボスは単元スコープ内。小学校既習、中学、高校以降、トリビアのラベルが正しいこと。
- 静的サーバーとfile直開き、PCとタブレット、キーボード、ルビOFF、音OFF、動きを減らす設定を検証すること。
- 外部API・画像・CDN・フォントを追加せず、アプリ本体をオフラインで利用できること。

この文書は将来の増補案も含みます。実装済みの範囲と検証方法は冒頭およびREADMEに記載し、教材全問の最終査読は別途行います。
